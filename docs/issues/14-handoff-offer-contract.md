## Problem and chosen boundary

The widget's card currently sends only a session ID and confirmation. If an
emergency card is followed by a fallback card, clicking the old emergency card
files a routine fallback ticket. Concurrent and delayed replies make disabling
old buttons alone insufficient.

Add an identity for the offer the customer confirmed. This contract PR prepares
that boundary; issue 15 will implement allocation, matching, stale rejection,
idempotency and the widget. This additive PR alone does not fix the bug.

## Implementation steps

1. Read all constructors and serialization assertions for `ChatReply` and
   `HandoffRequest`. Add the validation/round-trip tests described below before
   changing the contract.
2. Define one shared `OfferId` string alias in `contracts/chat.py`, using
   Pydantic's existing `Field(pattern=...)` approach for a canonical lowercase
   hyphenated UUID v4. Code will generate it with stdlib `uuid4` in issue 15.
   Do not use the session's resetting offer counter as the public identity.
3. Add `offer_id: OfferId | None = None` to both `ChatReply` and
   `HandoffRequest`. Defaults keep existing callers and saved replies readable
   during the contract-only transition. Do not require every handoff-bearing
   reply to have an ID in this transitional PR; issue 15 must populate it on
   every live card. Leave `confirmed: Literal[True]` required.
4. Semantics: non-null means that exact session's offer; null in a request is
   the header's explicit current-conversation action. An ID is not authorization
   to access another session. Stale/unknown IDs must eventually create no
   tickets and return HTTP 409 with the existing `HandoffReply` shape. Specify
   that behavior in comments; implement it only in issue 15.
5. Update all example replies because their tests require exact model round
   trips: a synthetic UUID for each example showing a card, explicit null for
   other replies. Keep text, sources and flags identical. The existing
   `HandoffReply` examples do not need new fields.
   Update the complete order-failure response assertion in
   `tests/assistant/test_app.py` for `offer_id: null`; the response and privacy
   behavior must otherwise remain identical.
6. Run `.venv/Scripts/python.exe -m tests.contracts.snapshots` (or `make contracts`)
   to regenerate. Verify only ChatReply/HandoffRequest entries change in
   `schemas.json`; mock API and model output schemas remain identical.
